# Сруб и пар: демо-сайт магазина бань с админкой

Учебный проект для портфолио: каталог на HTML/CSS/JS и бэкенд на FastAPI с админкой
для владельца. Компания, товары и цены вымышлены.

## Что умеет

- Каталог из базы: фильтр по типу, у каждого товара цена и наличие.
- Заявка с выбором модели. Название модели сервер берёт из базы, а не из запроса.
- Админка `/admin` (логин `admin`, пароль из `ADMIN_PASSWORD`): добавление, правка и удаление
  товаров, отметка «в наличии», список заявок. Владелец правит каталог без кода.
- Защита: проверка данных, ограничение частоты (5 заявок в час с одного IP), ловушка для ботов,
  защитные заголовки (CSP), данные на страницах выводятся как текст (не как HTML).
- Защита от CSRF в админке: изменения принимаются только с заголовком `X-Requested-With`,
  который чужой сайт подставить не может.

## Структура

```
banya-demo/
├── app/
│   ├── main.py         # маршруты, проверка данных, админка
│   ├── admin.html      # страница админки (отдаётся только после входа)
│   ├── security.py     # защитные заголовки, лимит размера запроса, фильтр спама
│   ├── formtoken.py    # одноразовые токены формы
│   ├── ratelimit.py    # ограничение частоты запросов
│   └── db.py           # SQLite, стартовые товары
├── static/
│   ├── index.html, 404.html
│   ├── css/            # style.css, motion.css (анимации)
│   └── js/             # main.js, admin.js, motion.js (плавное появление блоков)
├── tests/              # test_api.py, test_security.py, test_formtoken.py, test_ratelimit.py, test_db.py
├── render.yaml         # настройка деплоя на Render
└── .env.example        # образец настроек, копируется в .env
```

## Запуск у себя

```bash
conda create -n banya python=3.12
conda activate banya
pip install -r requirements-dev.txt
copy .env.example .env        # macOS/Linux: cp
pytest
uvicorn app.main:app --reload
```

Сайт: http://127.0.0.1:8000, админка: http://127.0.0.1:8000/admin

## Как менять стартовые товары

Список лежит в `app/db.py` (переменная `SEED`) и используется, только если таблица товаров
пустая. На обычной работе товары меняют через админку. Чтобы начать с чистого каталога,
удалите файл `data/shop.db` и перезапустите сервер.

## Деплой на Render

Как в прошлых проектах: репозиторий на GitHub, на Render New → Blueprint, ввести `ADMIN_PASSWORD`.
На бесплатном тарифе файловая система не сохраняется: после перезапуска база сбросится и
вернутся стартовые товары, а изменения из админки и заявки пропадут. Для демо это нормально,
для клиента нужна постоянная база.

## Безопасность

Что сделано в приложении:

- **Спам.** Скрытое поле-ловушка для ботов; одноразовый подписанный токен формы (выдаётся при загрузке
  страницы, проверяется подпись, возраст и то, что он не использовался); отсев ссылок в имени и комментарии;
  удаление невидимых и управляющих символов; повторная заявка с того же телефона за 10 минут не сохраняется;
  не больше 5 заявок в час с одного адреса.
- **Перегрузка.** Общий лимит запросов с одного адреса (по умолчанию 240 в минуту, ответ `429` и `Retry-After`),
  отдельные лимиты на выдачу токенов и заявки, ограничение размера тела запроса (16 КБ, `413`),
  предел числа хранимых заявок, таймаут базы данных. Лимиты хранятся в памяти ограниченного размера.
- **Взлом админки.** Закрытие входа после 10 неудачных попыток за 15 минут; сравнение паролей за постоянное время;
  на боевом сервере (Render) админка не включится со слабым паролем (короче 12 символов или из примера);
  ответы админки не кешируются; все данные выводятся как текст, а не как HTML.
- **Подбор данных и инъекции.** Все запросы к базе с параметрами (SQL-инъекции невозможны), строгая проверка
  входных данных, неизвестные поля игнорируются, суммы и названия товаров берутся из базы или считаются
  на сервере, а не из запроса.
- **Браузер.** Политика CSP (скрипты и стили только свои, без инлайн-кода), `X-Frame-Options`,
  `X-Content-Type-Options`, `Permissions-Policy`, `Cross-Origin-*`, HSTS по HTTPS. CORS не включён:
  сайт принимает запросы только со своего адреса.
- **Отказ без подробностей.** Ошибки проверки возвращаются без технических деталей, документация API отключена
  в боевом режиме, неизвестные адреса получают страницу 404.

Чего приложение **не может** сделать, и что нужно на уровне инфраструктуры:

- **Настоящий DDoS** (тысячи запросов с тысяч адресов) останавливают не в коде приложения, а на уровне сети:
  CDN и фильтрующий прокси (например, Cloudflare перед своим доменом), защита хостинга. Лимиты в коде спасают от
  одиночных ботов и простых перебирающих скриптов, но не от распределённой атаки. Запуск настроен с ограничением
  числа одновременных соединений (`--limit-concurrency`) и коротким таймаутом простоя.
- **Шифрование** обеспечивает хостинг (HTTPS на Render включён по умолчанию).
- **Персональные данные.** Демо хранит заявки в обычной базе без шифрования. Для боевого сайта с российскими
  клиентами нужны политика конфиденциальности, хранение данных на серверах в РФ (152-ФЗ), постоянная база и резервные копии.
- **Актуальность зависимостей.** Периодически обновляйте библиотеки и смотрите на уязвимости (`pip list --outdated`).

Перед запуском на боевом сервере: задайте длинный `ADMIN_PASSWORD`, не публикуйте `.env`, проверьте, что в репозитории
нет файлов `*.db`, включите `ALLOWED_HOSTS` для своего домена.

## Важно про данные

В демо не вводите реальные имена и телефоны. Для боевого сайта с российскими клиентами
понадобятся политика конфиденциальности под конкретную компанию, хранение персональных данных
на серверах в РФ (152-ФЗ) и постоянная база.
